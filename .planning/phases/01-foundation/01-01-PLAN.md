<threat_model>
## STRIDE Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | Login form | mitigate | Breeze authenticates against bcrypt-hashed password; throttling via LoginRequest rate limiter |
| T-01-02 | Tampering | All POST forms | mitigate | Laravel `@csrf` directive + VerifyCsrfToken middleware on web group (Breeze defaults) |
| T-01-03 | Information Disclosure | Password storage | mitigate | User model casts `password => hashed` (bcrypt); plain text never persisted (AUTH-05) |
| T-01-04 | Elevation of Privilege | Session fixation | mitigate | Breeze regenerates session on login (`$request->session()->regenerate()`) and invalidates on logout |

**Assets:** User credentials, session tokens.
**Attack vectors:** Credential stuffing, CSRF, session fixation/hijacking.
**Mitigations:** Breeze bcrypt auth, CSRF tokens on all forms, session regeneration on login/logout, login throttling.
**Residual risks:** Role-based access control and inactive-user blocking are NOT yet present (delivered in Plan 04). Until then, any valid credential reaches the default dashboard.
</threat_model>

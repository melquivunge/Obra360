## STRIDE Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | Mass assignment | mitigate | `#[Fillable]` whitelist on User restricts assignable columns; role only settable via guarded admin flows (Plan 05) |
| T-02-02 | Repudiation | Data deletion | mitigate | SoftDeletes on users/clients/projects/photos/expenses/documents keeps deleted_at audit trail (SEC-06) |
| T-02-03 | Elevation of Privilege | role column default | accept | Default role is `client` (least privilege); admin assignment requires explicit seeder/admin action |
| T-02-04 | Information Disclosure | document visibility | mitigate | `visibility` column defaults to `interno`; client access filtering enforced in Phase 4 |

**Assets:** Role assignments, client↔user linkage, all persisted business data.
**Attack vectors:** Mass-assignment privilege escalation, hard-delete data loss.
**Mitigations:** Fillable whitelist, soft deletes, least-privilege default role, default-internal document visibility.
**Residual risks:** Verify the `role` column can never be mass-assigned from unauthenticated input — Plan 05's StoreUserRequest must validate role against the four allowed values.
</threat_model>

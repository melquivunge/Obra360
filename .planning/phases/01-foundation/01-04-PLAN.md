<threat_model>
## STRIDE Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | Cross-role route access | mitigate | EnsureUserRole middleware + Gates gate every admin route; client hitting /admin -> 403 (SEC-01) |
| T-04-02 | Spoofing | Inactive/disabled accounts | mitigate | LoginRequest blocks active=false users before a session is created (AUTH-04) |
| T-04-03 | Information Disclosure | Auth error messages | mitigate | Generic "E-mail ou senha incorretos." avoids revealing whether an email exists |
| T-04-04 | Denial of Service | Login brute force | mitigate | Breeze RateLimiter throttling retained in LoginRequest::ensureIsNotRateLimited |
| T-04-05 | Tampering | Password reset token | mitigate | Laravel signed/expiring reset tokens via password_reset_tokens table (Breeze default) |

**Assets:** Sessions, role authorization decisions, password-reset tokens, account-active state.
**Attack vectors:** Privilege escalation across roles, inactive-account login, account enumeration, login brute force.
**Mitigations:** Role middleware + Gates on all sensitive routes, active check before session creation, generic credential error, login throttling, expiring reset tokens.
**Residual risks (verify manually):** Confirm the inactive check runs so that Auth::logout fires and NO authenticated session persists for an inactive user (assertGuest in InactiveLoginTest is the gate). Confirm /admin is unreachable by client role (403, not a redirect loop).
</threat_model>
